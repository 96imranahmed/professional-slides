# Metric Page

This is a specialized composition profile, not a separate narrative archetype. Select [`chart-led insight`](chart-led-insight.md) when the metrics are the proof or [`executive synthesis`](executive-synthesis.md) when they summarize several already established branches, then apply this geometry through [`metric fields`](../components/metric-fields.md).

## Use when

One to three values can establish the magnitude, threshold, progress, or stage of the claim without a trend or distribution chart. Use another chart when the audience must understand how the value changed, how it is composed, or how it compares across many categories.

## Content contract

- one to three values with units, period, population, and source;
- comparable labels and one-line interpretation;
- one explicit hierarchy only when the title explains it;
- optional single terminal-action region when the metrics directly govern a decision.

## Layout

Use the open metric row by default. Align values to one baseline, place a short quiet divider beneath each value, then align label and explanation. Do not default to individual cards. Use the hero-plus-peers variant only for a real dominant metric and keep peers structurally identical.

## Structural HTML reference

Use the open-row, hero-plus-peers, decision-band, or compact-strip structures in [`metric-fields.md`](../components/metric-fields.md#structural-html-reference). Bind all states to the deck's token registry and source zone.

## Failure modes

Vanity metrics, incomparable periods, missing denominators, decorative cards, unexplained highlighted values, labels that repeat the number, and a second CTA beneath the metric implication.

## Acceptance test

The action title and the values state the same conclusion, every value is interpretable without narration, and replacing the metrics with prose would make the proof slower rather than more rigorous.
