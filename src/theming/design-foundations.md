# Design Foundations

Use these rules to turn a business question into a coherent consulting deck.
Explicit user direction and an approved reference deck override the defaults.

## 1. Start with the decision

Define the communication job in one sentence:

> By the end, **[audience]** should **[outcome]** because **[governing thought]**.

The governing thought is the shortest defensible answer to the deck's central
question. It should be specific enough to disagree with and strong enough to
organize every chapter. If the work is exploratory, state the exact questions
the analysis resolves rather than forcing a recommendation.

### Build a horizontal logic

Organize the governing thought into three to five non-overlapping supporting
claims. Together, the claims should be sufficient to support the answer. Test
the sequence by reading only chapter headlines and action titles.

Useful arcs include:

- context -> tension -> evidence -> recommendation -> action;
- question -> analysis -> answer -> implication;
- current state -> root causes -> future state -> transition plan;
- options -> criteria -> evaluation -> recommendation;
- objective -> workstreams -> milestones -> governance.

An agenda is navigation, not a storyline. Each chapter must advance the logic.

### Build vertical logic

Within a slide, the title states the claim, the exhibit proves or explains it,
and the takeaway states the consequence. Every element should support the same
narrative job. If two unrelated claims remain, split the slide.

## 2. Write action titles

An action title is a complete, audience-facing sentence that communicates the
slide's answer. It is not a topic label.

Prefer:

- "Specialist routing can remove 30% of avoidable resolution time"
- "Two customer segments generate most profitable growth"
- "A phased pilot contains risk while proving unit economics"

Avoid:

- "Resolution time"
- "Market analysis"
- "Key takeaways"
- titles that merely describe the visual, such as "Revenue by region"

Keep the title to one or two lines in the chosen template. Use sentence case
unless the reference system clearly does otherwise. Do not end titles with a
period unless the theme consistently does.

### Title quality test

The title should answer at least one of these questions:

- What changed?
- Why does it matter?
- What explains the result?
- What choice follows?
- What must happen next?

Read all titles in sequence. They should function as a concise executive memo.

## 3. Allocate the canvas

Use a 16:9 canvas by default. Establish a consistent content frame before
building slides. The exact measurements come from the theme, but these
proportions are a reliable starting point:

- left and right margins: 5% to 7% of slide width;
- top title zone: 13% to 18% of slide height;
- body zone: 68% to 76%;
- source/footer zone: 4% to 7%;
- internal gutters: 1.5% to 2.5% of slide width.

Use a 12-column construction grid for flexible composition and a 6- or 8-point
spacing unit for alignment. A grid is an authoring aid and must not be visible
in the final deck unless the user explicitly requests it.

Align objects to shared anchors. Prefer a few strong horizontal and vertical
lines over many approximate alignments. Equal visual weight matters more than
mathematical equality when shapes or labels differ.

## 4. Control visual hierarchy

Every slide needs one obvious first read, one clear second read, and quiet
supporting detail.

Use hierarchy in this order:

1. position and scale;
2. whitespace and grouping;
3. typography weight;
4. color emphasis;
5. rules, fills, or enclosures.

Do not make every item bold, colored, boxed, or icon-led. Repetition creates a
system; exceptions create emphasis. Use one accent color to carry the argument
and neutral tones for context.

### Density budgets

Choose a density mode intentionally:

- **Live presentation:** one main visual, minimal copy, body text typically
  18 pt or larger.
- **Executive pre-read:** one main exhibit plus concise explanation, body text
  typically 14-18 pt when the reference supports it.
- **Analytical appendix:** denser tables or methods, never at the expense of
  legibility at 100% zoom.

Do not compress an appendix page into the main story. Move detail out of the
core deck instead.

## 5. Use typography as a system

Use one sans-serif family with a small, intentional weight range. A second
family is acceptable only for a deliberate display role established by the
theme.

Unless a reference deck specifies otherwise, begin with:

- deck title: 30-36 pt;
- slide action title: 22-28 pt;
- section number/title: 26-34 pt;
- exhibit title or subheading: 16-20 pt;
- body: 14-18 pt;
- chart labels and table text: 10-14 pt;
- sources and footers: 8-10 pt.

These ranges reflect dense consulting documents. If the delivery environment
requires large-room readability, increase all levels. Never shrink text merely
to preserve a chosen layout.

Use bold for meaning, not decoration. Keep line spacing compact but readable,
usually 1.05-1.2 for titles and 1.1-1.3 for body copy. Use consistent paragraph
spacing rather than blank lines inside text boxes.

## 6. Make exhibits earn their space

The body should usually be one dominant exhibit:

- a chart for magnitude, trend, composition, change, or relationship;
- a table for exact lookup or multi-criteria comparison;
- a process for ordered actions or decisions;
- a tree for decomposition or causality;
- a map only when geography changes the conclusion;
- a small number of direct quotations when voice is the evidence.

Add an exhibit subtitle only when it clarifies the measure, scope, period, or
unit. Put the conclusion in the action title, not in a generic chart title.

## 7. Write for scanning

- Lead bullets with the conclusion, then support it.
- Keep bullet grammar parallel.
- Use specific nouns and active verbs.
- Replace vague qualifiers with evidence.
- Avoid jargon that the intended audience would not use.
- Do not expose analysis instructions, template directions, or production
  notes in visible slide copy.

Use a maximum of two indentation levels. If a bullet requires a paragraph,
convert it to a short statement plus evidence or move it to notes.

## 8. Use visual restraint

Default to flat, editable compositions. Avoid 3D treatments, gradients without
a semantic role, shadows, bevels, decorative photos, pseudo-UI cards, and icon
collections. Use photography only when a real subject, place, product, or human
story is part of the evidence.

Simple diagrams should use consistent native shapes and connectors. Add a
diagram only when spatial structure materially improves comprehension. Do not
turn a straightforward list into a decorative process.

## 9. Preserve provenance

Every non-trivial external claim and visual needs a traceable source. Show a
concise source line on the slide and retain the full citation, retrieval date,
calculation notes, and file or URL in speaker notes or a source ledger.

Label data honestly:

- actual, estimate, forecast, scenario, or illustrative;
- calendar or fiscal period;
- currency and nominal/real basis;
- sample size and important exclusions;
- rounding and calculation method when material.

Never present illustrative values as verified evidence.

## 10. Review the story before polish

Before visual QA, verify:

- the opening establishes the decision and stakes;
- the executive summary contains the answer, reasons, and action;
- each chapter supports one branch of the governing logic;
- each action title is proven by its exhibit;
- implications are explicit;
- the close resolves the opening and makes the decision or next step clear;
- the appendix contains supporting depth without hiding essential evidence.
