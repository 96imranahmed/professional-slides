# Hypothesis Tree

This file owns the problem hypothesis tree and 80/20 analytical prioritization. [`index.md`](index.md) owns the deck's overall narrative workflow, while [`dot-dash.md`](dot-dash.md) owns how prioritized hypotheses map into the storyline.

## Build the tree

Start with the problem in question, not a proposed page list. Write one precise root question whose answer would enable the communication job. Decompose it into mutually exclusive and collectively sufficient branches, then state each branch as a testable provisional answer. An issue tree asks what must be investigated; a hypothesis tree records what is currently believed and what evidence would confirm, refine, or reject it.

The hypothesis tree is a problem-solving control artifact even when it never appears in the deck. If the audience must see the tree, use the [`decomposition` slide type](../slide-types/decomposition.md) to present only the decision-relevant levels; do not let the visual archetype redefine the analytical branches.

Assign stable IDs such as `H1`, `H1.1`, and `H1.2` so the tree remains traceable as the story changes. For every terminal hypothesis, record:

- the provisional answer and its causal or logical relationship to its parent;
- the decision consequence if it is true and if it is false;
- the confirming or disconfirming analysis, measure, comparison, or evidence;
- the current evidence state: supported, contradicted, mixed, untested, or blocked;
- the source or data dependency and any material limitation;
- the priority and disposition: core story, appendix, parked, or unresolved.

## Apply 80/20 prioritization

Prioritize the tree rather than investigating every branch equally. Work first on the small number of hypotheses most likely to change the decision, resolve the largest uncertainty, or account for the greatest value or risk.

Stop expanding or polishing a branch when additional work is unlikely to change the governing thought at the required confidence. Retain lower-priority branches in the tree with an explicit disposition so focus does not become silent omission. Do not use 80/20 as permission to ignore a branch that could reverse the recommendation, conceal a material risk, or invalidate the evidence base.

## Acceptance check

- Siblings use one decomposition logic and do not overlap materially.
- The branches collectively answer the root question at the level required for the decision.
- Each leaf is falsifiable and specific enough to test.
- No conclusion depends on an unstated branch, hidden assumption, or circular claim.
- Every material evidence gap has an owner, resolution path, or explicit decision consequence.
- Every branch has a priority and disposition, including work intentionally parked or moved to the appendix.
