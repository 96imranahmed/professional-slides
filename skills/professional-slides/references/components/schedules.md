# Shared time schedules

`timeline` owns `time-grid` and `dated-lanes` alongside its simple `process` variant. Use them when the reading task requires agenda, output or responsibility records on one time domain. Do not substitute independent process cards or an unrelated date table: that removes the common axis.

`time-grid` requires `axis: {kind: "periods", precision, periods: [{id,label,startLabel?}]}`, lanes with stable IDs, labels and keyed events, plus `eventKinds` with direct legend labels and `triangle` or `open-circle` symbols. Optional agenda bands contain keyed text items at an exact `periodId`. Every symbol refers to a declared kind and period. Simultaneous events occupy the same time cell with independent glyphs; their small separation decodes event kind, never within-period timing. Empty cells contain no invented status. Agenda text may use `labelSpanPeriodCount` only with an explicit `spanPurpose` explaining that the span provides wrapping room, not duration; colliding spans reject.

`dated-lanes` requires `axis: {kind: "date", scale: "elapsed-days", precision: "day", domain: [ISODate,ISODate]}`, lanes and events keyed to an exact lane and date. Position follows elapsed days, not input order or equal spacing. Event labels keep date, subject, duration, location and qualification together. A continuous activity declares `extent: "visible planning horizon"` and an `extentQualification`; the visible rail is not evidence of exact start or completion dates. Supplied relationships require exact event endpoints, kind and evidence basis; a reserved corridor connects the first two adjacent lanes with native directional arrows, with approval above refinement. Other routing topologies reject until they have a measured canonical treatment. Unknown IDs, invalid dates, undeclared scales and insufficient geometry reject.

Both variants measure text using the active theme before allocating rows. `labelTreatment: "prominent"` binds primary schedule evidence to `type.heading`; the standard treatment uses `type.body`. Select the treatment for the whole schedule family. Prominent evidence is 16pt at executive density and 18.4pt at live-pitch density under the default theme. This is a semantic role binding, not a local font-size override. Dated lanes accept `dateTreatment: "body"` when dates are a primary lookup field: all event dates then use `type.body` (16.1pt at live-pitch), while source qualifications remain subordinate. The default `dateTreatment: "source"` keeps dates at the source role. Event subjects, durations, locations and local uncertainty retain their primary role. Week labels and agenda text share the primary role because they form a common lookup grid.

`spacing: "tight"` uses `space.1` instead of `space.2` for internal clearance without changing any type size. Axis height includes both the label field and all period labels; legends and lane rows reserve their measured text heights. `labelWidth`, `eventLabelWidth`, and per-event `labelWidth` are content-driven geometry inputs. Ordered event label boxes pack within each lane while event points retain their exact dates. Stems occupy an empty strip between labels and the rail, and relationship arrows occupy the reserved space between the first two lanes. They must not cross prose. An impossible set of widths or an overflowing frame rejects; do not reduce font size to force it through.

For an event at the right terminal edge of its packed label frame, both date and event text align right toward the marker. The exact elapsed-day point stays fixed. This keeps a terminal event attached to its label without moving its date to accommodate prose. Larger date roles participate in the same measured box height and collision checks as the event body.

Abbreviated lane labels need an expanded, referenced qualification when the abbreviations are not otherwise defined. A continuous-activity lane has a qualified horizon rule beneath its activity text. Qualifiers use the source role and exact `relatedTo` or `appliesTo` references. Record IDs must remain distinct after canonical ID normalization and must not collide with generated `-text`, `-date`, `-rule`, `-rail`, `-stem` or other object IDs. Invalid references, non-text event details, unknown treatments and spacing values reject. More rows or longer labels require more canvas, a coherent page-level density choice or a different composition. Use source comparison to check legibility and shared-axis reading, not merely whether all strings survived.

Implementation and shared token inventory: `runtime/schedules.mjs`. All objects are native editable primitives with exact dependencies; both rendering adapters and the complete golden set must validate the final batch.
