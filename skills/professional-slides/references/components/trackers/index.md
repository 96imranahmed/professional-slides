# Trackers and Navigation

A tracker answers one question: where are we in the deck? It is never an executive summary, scorecard, progress report, risk view, or status dashboard.

## When to omit it

Default to no visible tracker for live pitches, short decks, and simple two-part stories. The action-title sequence usually provides enough orientation. Never place a tracker on the executive-summary slide.

Use a visible tracker only when the audience would otherwise lose its place. Full tracker pages should mark a real change in the governing question and normally precede at least three analytical slides.

## Choose one system

| System | Use when |
| --- | --- |
| Top bar | Three to five short chapters need persistent orientation. |
| Sidebar | A stable list must remain visible across many pages. |
| Full-page grid | Peer chapters should be scanned together. |
| Badged list | A sequential story has longer chapter labels. |
| Segmented full state | A long pre-read needs orientation only at material transitions. |

For long consulting pre-reads, usually above roughly twelve slides, prefer a contents page plus the same segmented full-state system at real chapter transitions. Keep analytical pages free of the four-segment rail.

## Parent and chapter hierarchy

A hierarchical tracker is one navigation system with two levels:

- The **parent tracker** names the deck-level chapters. Show its full state on the contents page and chapter transitions. On an analytical page, retain the active parent as a quiet label rather than repeating the full rail.
- A **chapter tracker** names the analytical subgroups within one parent chapter. Each parent owns its own chapter tracker. Show only the active parent's child items and mark exactly one item active on each governed analytical page.

The hierarchy must be parallel to the approved dot-dash. Parent IDs equal section IDs; chapter-item IDs equal analytical subgroup IDs; labels and order remain exact; governed slide ranges are contiguous. Cover, executive summary, and close do not inherit either tracker. Read the [grounded dot-dash example](../../storylining/dot-dash-example.md) for the full sequence.

Use `hierarchical-segmented` only when both levels materially help orientation. Otherwise use one flat system or none. Parent and chapter trackers are variants of the same system, not two competing navigation grammars.

## Tracker contract

Define the tracker once from the approved story:

- stable item IDs, labels, order, and slide ranges;
- one active item per tracked page;
- one full state and, only if needed, one compact state;
- clear visibility rules for cover, contents, analytical, close, and appendix pages.

For `hierarchical-segmented`, also define the parent item ID and chapter item ID on every governed analytical slide. The compact analytical header uses the exact parent label plus the exact active chapter label. Do not concatenate a page topic into either label.

Use the exact approved label wherever it appears. A label-bearing variant cannot appear intermittently inside its declared range. Do not concatenate a subsection or page topic into the tracker label.

## Visual rules

Use one `component-primary` accent and neutral states. Do not use chart-series colours, RAG colours, or decorative per-item colours. Keep the tracker secondary to the title and evidence.

Use one tracker system across the deck. Do not mix top bars, sidebars, grids, or slide-local substitutes.

## Check

- The tracker communicates navigation only.
- It is absent when it adds no orientation value.
- Labels, order, active state, and ranges are consistent.
- Structural edits update tracker ranges, page numbers, and cross-references.
- The montage shows no stale, skipped, or duplicated state.
